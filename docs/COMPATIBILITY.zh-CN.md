# 正常开发工作盘兼容性契约 v0.2

日期：2026-10-24。**所有功能为验收要求，不是已实现声明。** 本文取代 v0.1 中把开发工具及复杂链接整体排除出 V1 的范围。

## 1. 产品必须做到什么

用户在 Finder/Explorer 挂载工作卷后，普通程序通过系统文件接口直接读写。Codex 本地代理可以选择卷内项目，搜索、修改、创建与删除文件，在授权范围内调用终端运行依赖安装、构建和测试。Git、IDE 与代理能同时使用同一卷，而非各自在隐藏的内置盘副本上工作。

软件自身的认证资料、系统工具和操作系统本来就使用的临时目录可以仍在系统盘；这不同于为了掩盖缺陷强制把源码、node_modules、.venv、target 或数据库迁出卷。测试要特意把这些项目内容放在挂载卷内。

“正常工作盘”要求正确实现相关文件操作，不是承诺它可用作系统启动盘、交换文件、裸盘分区/格式化目标，或支持每个 APFS/NTFS 私有控制接口。不支持的特殊控制请求应返回规范错误，不能导致文件损坏、服务崩溃或假成功。涉及普通开发操作的缺陷不能仅以“非目标”关闭。

## 2. 文件系统语义门禁

| ID | 必须验证的行为 | 重点风险 |
|---|---|---|
| FS-01 | 创建/读写/追加/随机覆盖/截断/空文件/越过 EOF 后读零 | 短写、偏移溢出、缓存不一致 |
| FS-02 | 原子替换、同目录/跨目录重命名、仅大小写改名 | 编辑器安全保存、Git index.lock |
| FS-03 | 稳定文件身份、打开后改名/删除、多进程访问 | 不能将路径当唯一 inode；区分 POSIX 与 Windows 共享语义 |
| FS-04 | 文件与目录同步、错误回传 | flush 失败不能成功；GC 不得破坏已同步内容 |
| FS-05 | mmap 读写与可执行映射、动态库/原生程序加载 | 不能仅验证解释器读取脚本 |
| FS-06 | 符号链接、目录链接、相对目标、断链 | 不能复制文件冒充链接；按授权规则解析路径 |
| FS-07 | 硬链接、共同文件 ID/内容、link count、unlink | WinFsp 文档缺口为 BLOCKED；不能复制替代 |
| FS-08 | 独占创建、跨进程字节锁/共享模式、锁释放 | SQLite、Git、并发构建 |
| FS-09 | 目录事件、更新/替换后的缓存失效、监听溢出处理 | IDE、热更新；轮询降级只能明确标注，不算事件接口通过 |
| FS-10 | Unix mode/执行位、Windows ACL 强制与继承 | 存字段不等于权限实际生效 |
| FS-11 | xattr/资源分叉/备用数据流/安全标记 | 不静默丢弃 quarantine 或 Zone 信息 |
| FS-12 | 大小写、Unicode、长路径、保留名、名称冲突 | 两端比较规则固定，不能暗改名称 |
| FS-13 | 实际可用空间/逻辑配额/分配大小 | 不把待回收字节当可用；ENOSPC 不写坏元数据 |
| FS-14 | 安全卸载、忙碌句柄、睡眠/唤醒、介质消失 | 不虚报安全弹出；旧句柄不指向重挂后的另一卷 |

首版采用大小写保留、不区分大小写的固定名称规则；大小写冲突项目必须明确诊断，不能静默覆盖。大小写敏感卷若增加，需独立格式能力位与双端验证。平台专属权限不能简单互相一对一翻译。

## 3. 开发工具实际工作流

| ID | 必测闭环 | 位置及通过条件 |
|---|---|---|
| DEV-01 | Git init/clone/status/diff/add/commit/checkout/merge/gc/fsck | .git 在卷内；失败不留错误锁或损坏对象 |
| DEV-02 | Git worktree 增删与多工作树并发编辑 | common git dir 和工作树都要覆盖卷内组合 |
| DEV-03 | npm/pnpm 本地及缓存依赖安装、执行、删除重装 | node_modules 在卷内；记录链接模式与回退，不能当硬链接通过 |
| DEV-04 | Python venv、pip/uv 安装、import、原生扩展 | .venv 在卷内；uv 默认和明确 copy 模式分开记录 |
| DEV-05 | Rust Cargo、原生编译、增量构建、测试二进制 | target/产物在卷内并从卷内执行；跨 OS 正常重建 |
| DEV-06 | VS Code 等编辑器安全保存、搜索、文件树刷新、热重载 | 不只验证在编辑器里打开一个文件 |
| DEV-07 | 项目 SQLite rollback/WAL、跨进程锁、mmap、checkpoint | 是用户卷内的数据库，不只是后端 catalog 能工作 |
| DEV-08 | ZIP/TAR、复制/移动/回收站、解压后属性与链接 | 以工具声明语义为准，失败不静默丢信息 |
| DEV-09 | 多终端/编辑器/代理并发 + 自动 GC | 对相同文件的冲突按平台规则处理；GC 不改变逻辑文件身份 |
| DEV-10 | Mac→Windows→Mac 往返编辑和重新构建 | 同一容器，内容/承诺属性核对；不要求跨 OS 执行彼此的二进制 |

pnpm 官方文档描述了符号链接和硬链接布局 [S15]；uv 也区分链接与复制 [S16]。工具合法回退到复制可以记为“该工作流在此模式可用”，不能把严格硬链接用例改成通过，也不能隐瞒性能/空间代价。

## 4. Codex 必须单独验收

### 4.1 运行位置

本地 CLI、桌面/IDE 本地代理、Windows 原生、Windows/WSL 是不同矩阵。云端任务在远程环境运行，不会因为本机挂载了一个卷就自动看到本机路径 [S13–S14, S17]。WSL 的盘符可见性、DrvFS 行为、Linux 权限/链接/监听另测；不以 Windows PowerShell 的结果代替。

### 4.2 正向和反向测试

1. 保存 OS、客户端版本、驱动版本、挂载类型、卷 ID、实际 cwd 和使用的权限策略，不能仅写“Codex 支持”。
2. 选定卷内一次性测试仓库。按当时官方支持的配置将它设为可写工作区，维持正常沙盒和审批策略；不写入全局宽松配置，不使用危险绕过选项。[S13][S14]
3. 在该路径启动实际代理，让它读取项目、修改源文件、新建和删除测试文件、调用项目测试并修复一个可验证的错误。产物保持在卷内；人工核验 diff 和测试结果。
4. 通过正常授权测试需要写入 .git 的 Git 工作流。一些权限模板保护 .git/.codex 等路径；与普通盘做相同策略对照，不能把政策规定的拒绝误诊为存储故障，也不能绕过它。[S13]
5. 沙盒外放置仅用于测试的哨兵文件，确认策略规定禁止的写入确实失败且内容未变。符号链接逃逸、路径大小写/规范化、另一个盘符别名也不能绕过边界。
6. Windows 额外验证受限 token/独立沙盒用户/适用隔离模式能看到授权盘符，能够执行允许的操作；不通过把卷开放给 Everyone 或赋管理员权限解决。
7. Codex 退出/异常终止后，另一个普通进程应看到已正确提交的修改；锁应按规则释放。重挂卷后运行 git fsck 和内容校验。

不将某个版本的沙盒模式写死为永远唯一实现。官方目前区分 macOS、Windows 原生和 WSL 的隔离机制；Windows 也有不同实现及设备条件，测试记录具体选择 [S13][S14]。

### 4.3 权限威胁边界

内部 Windows ACL/Unix mode 必须被文件系统真实执行。管理 IPC 可只准卷 owner；操作文件的应用身份则要按 ACL/token 正确授权，不能把“owner-only 管理”误做成拒绝合法 Codex 沙盒用户访问文件。

外层 exFAT 缺少 ACL [S1]。内部 ACL 不能阻止一个已被允许直接读取/修改 .pwvol 原始目录的进程绕过内层卷。受限代理的策略必须限制原始 backing 目录，并测试不能从原始段/数据库绕过声明的边界；未证明前不得声称多用户机密隔离。未加密卷也不提供物理访问者保密性。

## 5. 后端选择与阻断处理

截至此次核验，WinFsp 官方仍把硬链接、部分 FSCTL、USN 等列为未支持 [S12]。基础复制通过不关闭 FS-07。先复现和记录精确版本，再评估可维护的上游扩展、经审查的替代后端或更深的原生接入。未通过前保留 BLOCKED，不能宣传“等同 NTFS”。

FSKit 的 API 文档只证明开发接口存在，不证明我们的文件系统具备执行、监听、缓存和沙盒兼容 [S2–S4]。真机逐项测试，不从某个第三方 FSKit 后端的限制推导所有实现都不可能。

项目开发体验优先于原定驱动选型；同时不仓促承诺“直接写个内核驱动就能解决”。自研或分发驱动需要单独安全、签名、许可、升级和恢复审查。

## 6. 证据与发布规则

结果状态：PASS / FAIL / BLOCKED / NOT_RUN / NOT_APPLICABLE。必须记录配置与复现命令。缺工具、没真机、没有授权都不是 PASS；不能只给一个绿色总数掩盖缺项。

普通目录探针属于测试工具自身的基线；passthrough 原型只证明接入路径；只有同一个真实 .pwvol 容器在两端的工作流与故障结果才能支持产品兼容声明。任何数据损坏、权限绕过、假成功或 GC 误删阻止发布。应用和驱动升级后重跑受影响矩阵。
