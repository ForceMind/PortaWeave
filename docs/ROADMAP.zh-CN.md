# 研发路线与发布门禁

所有未勾选项均未完成；文档存在不代表实现存在。开发工作盘契约优先于原定平台接入选型。

## M0：先证明平台能承担正常工作盘

- [ ] 固定候选 SDK/驱动版本、许可与签名条件，建立各系统原生基线。
- [ ] FSKit 与 Windows 候选真实挂载；明确不是普通目录或网页演示。
- [ ] 执行/可执行 mmap、缓存失效/监听、链接、锁与 ACL 逐项验证。
- [ ] 复现 WinFsp 硬链接缺口，形成可验证解决方案；未解决保持 BLOCKED。
- [ ] Codex 本地工作区在正常沙盒内读写、执行测试；沙盒外写入仍被拒绝。
- [ ] exFAT 上 SQLite VFS/同步/锁与卷独占；原始 backing 目录权限威胁核查。
- [ ] Windows 原生与 WSL 单列报告，不相互替代。

## M1：Rust 共享引擎与故障测试

- [ ] 格式版本/能力位/UUID、稳定对象 ID、目录项及链接模型。
- [ ] SQLite 元数据、追加段、随机读写/截断、原子目录更新与平台错误映射。
- [ ] 整段回收、并发混合段迁移、读者 pin、GC 预算与中断恢复。
- [ ] 正确同步、空间不足/短写/校验失败、每个提交边界故障注入。
- [ ] 无 GUI/驱动依赖的 verify/export，恢复保全原件，安全升级策略。

## M2：真容器双端开发闭环

- [ ] Mac→Windows→Mac，使用同一容器，不重建一个替代格式。
- [ ] Git/worktree、npm/pnpm、venv/pip/uv、Cargo、原生构建与程序加载。
- [ ] IDE 保存/搜索/通知、SQLite/WAL、并发应用 + GC。
- [ ] Codex CLI/桌面或 IDE 本地模式的版本化验收；按授权执行真实代理。
- [ ] 普通应用、系统文件管理器、回收站、xattr/ADS、休眠与忙碌卸载。

## M3：可靠性与容量

- [ ] 模型测试、随机状态机、GC/读写竞争、ENOSPC/EIO/同步错误。
- [ ] 专用授权介质的异常断开与恢复；模拟测试和物理测试分开。
- [ ] 对照普通 exFAT 与原生盘，报告吞吐、尾延迟、写放大和维护开销。
- [ ] 所有静默错读、假成功、权限绕过、误回收为零；不能以平均成功率抵消。

## M4/M5：可安装测试版与稳定版

- [ ] 桌面管理器、安装签名/公证、忙碌原因、容量与回收状态。
- [ ] 卸载程序不删除用户容器，更新不静默迁移唯一副本。
- [ ] 冻结格式与明确的兼容矩阵，回归与恢复演练，已知边界可见。

加密/快照/去重/压缩/Linux 原生后端不抢占上述基础能力。缺少测试硬件不伪造完成；继续当前环境能够验证的核心工作，不承诺会话结束后后台开发。
