# M1-C：宿主容量准入与数据段 I/O 故障保护

日期：2026-10-24。基于主分支 `ad6506a571ed923f4e114168cf901d2cab7bbe56`，不重建已有核心、不改变 `experimental-m1a-block-v1` 格式。本增量是 #3 的部分推进；仍不是可挂载磁盘，不代表 Codex 或 exFAT 硬件兼容。

## 1. 写入前容量检查

新增 `space_status()`、`SpacePolicy` 和 `Stats.space`。通过固定依赖 `fs2 = 0.4.3` 读取宿主文件系统对非特权调用者可用空间。默认软水位为 16 MiB，再加 1 MiB 元数据余量；`set_space_policy` 校验算术溢出并只改变当前 owner 的策略，不持久化到容器。

每次 stage 在分配 SQLite 段 ID 之前，计算本次完整数据段的编码字节数（24 字节段头 + 64 KiB 块数），再加软水位和元数据余量。单字节覆盖也可能需要新写一个整块；不能拿用户传入的字节数替代实际写时复制成本。使用 checked arithmetic，待回收垃圾不计入已可用空间。

`Error::HostSpace` 表示准入拒绝，尚未写入此次新段或分配其目录身份；它不锁定写保护。旧内容/引用/大小保持不变，空间恢复后可以重试。一般名称操作和无需新数据段的零长度截断仍可尝试执行，实际 SQLite/I/O 错误仍必须传播。

**这不是物理预分配、全局写入预约或已经创建的应急 reserve.bin。** 外层其他程序能抢占空间；SQLite/WAL、簇对齐、目录开销并非由 1 MiB 余量严格封顶。策略只能尽早拒绝明显不足的请求，不能保证预检通过后就一定写得进去。创建/打开数据库的分配也不在此数据段准入边界内。并发预约、按宿主分配单元计算预算、物理应急预留与完整低空间恢复仍待实现。

## 2. 自动回收的两类结果

新增 `MaintenanceStatus::DeferredSpace { available_bytes, required_bytes }`。所有者先回收没有有效引用的整段；遇到混合段迁移没有工作空间时，保持旧段和当前引用，返回业务成功，记录延期状态，不把它当作损坏，也不锁定写保护。

下一次触发维护的操作会重新检查。空间恢复后可自动完成迁移并恢复 `Healthy`。当前仍是串行操作触发，尚无空闲线程、定时任务或卸载后后台运行。

真正发生在 stage/同步/SQLite 中的错误与预检拒绝不同：沿用 `Io`/`Sql` 错误并锁定写保护。若该错误发生在业务提交后的维护，原业务结果仍成功，维护状态为 `Failed`。不得为减少错误提示先删除唯一旧副本，不自动清空用户回收站。

部分块截断需要先保存归零的新尾块，空间不足时可能被拒绝；截断到零不需要新数据段，但元数据事务仍可能失败。因此不能宣传“磁盘绝对满时删除一定成功”。

## 3. 数据段 I/O 测试接口

新增 `SegmentFile` I/O 包装层，生产默认构建保留正常写入与同步调用，但不包含故障控制 API。启用 `fault-injection` 后，`inject_storage_fault_once` 只作用于该 owner 下一次实际创建的数据段，不使用进程环境变量或全局共享故障状态。

可测试：有限进度短写、一次 Interrupted、写入一段前缀后 WriteZero、StorageFull 或其他 I/O 错误、数据同步失败及目录同步失败。短写有进展时应由 `write_all` 继续完成；零进展必须成为 WriteZero，不能伪报成功。新数据未完整写入并同步前不会更新有效文件引用。

目录同步失败钩子验证错误传播，不填补 Windows 缺少便携目录 fsync 的实现空缺。数据同步钩子在真实同步调用前返回错误，不模拟设备谎报成功、掉电丢缓存或撕裂持久化。

`set_test_available_space` 仅将可用量限制在真实宿主量之下，不能制造虚假的更多可用空间。两个 owner 的故障状态相互独立。不得为用户客户端启用故障注入特性。

## 4. 新增测试的具体边界

`tests/space_io.rs` 覆盖容量快照/策略溢出、写前拒绝无副作用、写时复制全块预算、部分截断与清空、低空间整段删除、混合段延期与重试、短写/Interrupted 正确重试、五类 stage 故障后旧内容和读取租约保留、重新打开清理孤儿、维护失败不冒充业务失败、owner 局部故障状态。

`space_catalog_tests` 使用真实 SQLite `PRAGMA max_page_count` 产生 `SQLITE_FULL`，验证原错误被返回、写保护生效、旧内容可读且重开一致。它不是物理磁盘写满，也不代替 SQLite VFS 的短写/同步故障测试。

现有三系统核心工作流运行默认与全部特性构建、静态/格式检查，Linux 10 轮并行回归新增 `space_io`。同一容器接力继续使用原有四阶段 CI。实际通过状态必须引用对应源 SHA 的 Actions/PR 记录；本文不预先声明尚未结束的测试成功。
