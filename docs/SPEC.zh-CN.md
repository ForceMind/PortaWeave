# PortaWeave（随卷）产品与工程规格 v0.2

日期：2026-10-24  
状态：开发工作盘目标规格；已有实验性 Rust 核心及原生接入工程，双端挂载实测与断电测试尚未完成。实际实现范围见各 IMPLEMENTATION 文档。名称不代表商标或域名已核验。
仓库：`ForceMind/PortaWeave`；用户已创建，主分支 `main`，保持现有公开状态。

**v0.2 强制变更：本产品必须支持正常开发工作盘工作流，包括 Codex、Git、依赖安装、构建、运行、文件监听与权限检查。不得以“只支持资料读写”规避这些要求。详见 `COMPATIBILITY.zh-CN.md` 与 `adr/0001-development-volume-backend-gate.md`。后端选型须通过兼容性门禁，FSKit/WinFsp 目前均不是已验证的完整方案。**

## 1. 产品定义

把一个位于 exFAT 移动硬盘上的目录容器，挂载为 macOS Finder 或 Windows 资源管理器能够直接读写的文件卷。两端使用相同的 Rust 数据格式与存储核心；空间按写入增长，永久删除或覆盖产生的无引用数据自动回收。

这是用户态文件系统，不是 APFS/NTFS 驱动、裸块设备或虚拟机磁盘。普通文件访问走本地接口，不需要账户、服务器、互联网或数据上传。两端需要安装客户端；Windows 候选路线需要安装 WinFsp 等经审查的接入组件。不能宣传免安装。

第一版范围：一个本地物理设备、同一容器一个挂载所有者、两台电脑顺序交接。禁止同一底层容器跨电脑同时写入，也不支持把活动容器放入 SMB/NFS 或云同步目录。跨系统应先安全卸载，再移动介质。外层 exFAT 上的普通文件不受产品管理。

目标系统：首批拟支持 macOS 26 系列 Apple Silicon、Windows 11 x64。实际最低小版本、Intel Mac、Windows ARM64、其他系统在 M0 与后续矩阵验证后确定，不凭 API 的出现版本声明产品兼容。

## 2. 核心产品行为

创建时选择容器路径、名称和逻辑配额；配额不是预占物理容量。写入受逻辑配额和宿主实际剩余空间共同约束。实际占用包括数据、元数据、日志、工作空间及明确展示的应急预留，不承诺与文件内容字节数完全相等。

默认开启自动回收。手动“立即整理”仅改变调度优先级；不作为日常必经流程。维护只在获得容器独占所有权的引擎中运行。卸载或退出挂载服务后不承诺继续回收，下一次挂载自动续办。

删除的语义必须明确：

| 状态 | 自动释放物理空间 |
|---|---|
| 文件移入系统回收站 | 不释放；文件仍然存在 |
| 永久删除但仍有打开句柄/映射 | 等待引用释放，尊重平台语义 |
| 永久删除且没有有效引用 | 提交删除后自动回收 |
| 覆盖产生旧数据 | 等待事务完成和读者退出后回收 |
| 数据被用户启用的快照引用 | 保留；V1 不提供用户快照 |
| 容器离线 | 不处理；下次挂载继续 |

不能为了腾空间静默清空回收站、删除快照、强制关闭应用或跳过提交顺序。空间回收不等同于安全擦除或 SSD TRIM。

## 3. 技术架构

```text
Finder / Explorer / Codex / Git / IDE / 构建工具
        │
macOS: Swift + FSKit   Windows: WinFsp Native API + Rust adapter
        │                        │
        └────── Rust storage core ──────┘
                 │
       SQLite 元数据 + 追加式数据段
                 │
        exFAT 上的 Work.pwvol/ 目录
```

macOS 优先直接实现 FSKit 扩展，以 Swift 薄层调用 Rust C ABI。M0 必须验证目录资源访问、授权、签名、生命周期、缓存、属性、文件同步与正常退出，不能仅以“FSKit 已发布”作为可行性完成证据。[S2][S3]

macFUSE 可作为研发对照或独立兼容适配器，不能默认使用其内核后端，也不能隐藏安装权限或许可条件。macFUSE 的 FSKit 后端文档仍列出通知、挂载选项和性能限制；这些限制不应未经测试等同于所有原生 FSKit 实现的限制。[S4]

Windows 以 WinFsp 原生接口作为待验证候选，优先复用经审查的 Rust 绑定；需要时使用极薄 C ABI。WinFsp 官方明确列出硬链接、部分文件控制接口等限制，不能仅因其能挂载就冻结选型。[S5][S12] 硬链接、执行映射、文件通知、ACL 与 Codex 沙盒的实测是 M0 阻断项；必要时评估上游扩展或其他驱动路线，不能降低工作盘要求。

桌面管理界面拟用 Tauri + TypeScript。UI 不直接访问活动数据库，不拥有唯一的数据副本。数据引擎与 UI 分离；管理界面退出不等于安全卸载。每个活动卷由一个明确的 owner 进程持有存储核心、数据库连接和后台维护调度；具体 macOS owner 归属在 M0 确认。

UI 和 CLI 通过仅限授权管理用户的本机认证 IPC 操作 owner，不开放 HTTP 监听端口，不采用临时网站替代原生挂载。管理 IPC 的身份限制不等于拒绝合法应用用户：文件请求按实际 token/ACL 或对应平台身份授权，特别验证 Windows Codex 受限账户与盘符可见性。

## 4. 容器格式

```text
Work.pwvol/
├── format.json             # 格式版本、卷 UUID、能力标识；不是事务提交指针
├── catalog.sqlite          # 唯一权威元数据目录
├── catalog.sqlite-wal      # 运行时可能存在，不可手动删除
├── catalog.sqlite-shm      # 运行时可能存在，不可手动删除
├── segments/
│   └── ab/<segment-id>.seg # 按标识分目录，避免外层目录无限膨胀
├── maintenance/
│   └── reserve.bin         # 明示的应急预留；参数待测试
└── session.lock            # 配合 OS 锁；文件存在不代表锁有效
```

Mac 可将目录注册为 bundle，Windows 可注册“打开/挂载”入口，但其本质仍是目录，不是单文件镜像。应用内展示为一个卷。外层系统仍可能创建 `.DS_Store` 等文件；不能承诺整块 exFAT 零系统杂文件。

V1 只设一个权威元数据事务层。不得再叠加一套自研超级块提交协议或独立权威日志，与 SQLite 争夺“哪个版本有效”的解释权。

SQLite 管理文件 ID、目录项、文件长度、时间、属性、数据范围映射、数据段状态、待回收任务与会话状态；大文件内容不放入一个巨大 BLOB。小元数据值可以入库，大资源分叉按数据流管理。

数据段为追加式记录。已提交内容不原地覆盖；段头与记录包含格式标识、对象 ID、文件偏移、有效长度、世代和校验信息。关闭的段不可再追加。校验能发现损坏，不能凭空恢复丢失字节，也不能提供防恶意篡改的认证保证。

初始实验参数：逻辑块上限 64 KiB、数据段目标上限 64 MiB。短记录不强制补齐到 64 KiB。二者须通过随机写入、连续大文件和小文件测试选择；格式自描述，不能因升级偷偷改变既有卷语义。

大文件优先使用相对独立的段，减少删除整文件时搬移他人数据；小文件聚合在共享段，避免对每个小块在 exFAT 上建立一个宿主文件。冷热分流是优化，不是正确性前提。

## 5. 持久化与事务协议

复用 SQLite 事务能力，不自研 B-tree 或数据库。拟使用 WAL + `synchronous=FULL`，macOS 按支持情况启用更强同步；具体 VFS、锁和刷新行为必须在真实 exFAT 上验证。[S6][S7]

构建固定经审查的 SQLite 版本，不直接依赖未知系统版本。依赖至少须包含官方 WAL-reset 缺陷修复（3.51.3 或相应受维护回补线含修复），发布时重新核验安全版本；这不是建议永久固定在 3.51.3。[S6]

写入基本顺序：

1. 为一次有界写入申请空间预算；读取和合成必要的旧块。
2. 在新位置追加数据，检查短写与 I/O 错误。
3. 将所依赖的数据和宿主文件状态按平台可用机制持久化；不能只刷新语言运行时缓存。
4. 在单个 SQLite 事务内更新范围映射、长度和回收任务。
5. 完成事务所要求的同步；正确完成上层文件系统的 flush/fsync/FlushFileBuffers 请求。
6. 旧数据进入延迟释放队列，只有当前引用与活动读者均不再需要时才能删除。

普通 write 返回与“设备已持久化”不是同一件事。不能因应用数据仍在其自身或 OS 缓存，就承诺所有已显示输入在拔盘后仍存在。承诺以已成功执行的同步边界和底层履约为条件；整个 100 GiB 复制过程也不是一个自动原子的事务。[S8][S9]

崩溃可能留下尚未引用的新记录；允许多占空间，不允许为了清理它们删除可能仍在使用的数据。恢复后按照权威目录及安全世代清理孤儿。遇到同步失败、校验失败或不明确状态，停止写入并保留证据。

WAL 和元数据也必须有空间回收：在建库时选择经过测试的增量回收设置，限制长读事务，闲时 checkpoint 并增量 vacuum；只有安全条件满足才截断 WAL。增量 vacuum 不等于 data segment GC。[S7]

## 6. 自动空间回收

### 6.1 触发与调度

删除、覆盖、截断、关闭已删除文件、挂载恢复都会触发回收评估。默认低优先级与有界执行；例如前台 I/O 空闲约 30 秒启动碎片整理，这是调优起点而不是完成时间承诺。

整段已失效时直接执行安全删除，不等待达到百分比阈值。混合段优先选择回收收益高的候选，单次只搬移有限数据，给前台 I/O 让路；低收益候选可等长空闲再处理。界面区分可回收、等待引用、待整理和实际已释放，不能把账面未引用字节冒充已归还 exFAT 的空间。

M0/M1 需比较 16/64/256 MiB 段等实验组合；禁止未经测量宣传某一块大小为最佳。

### 6.2 混合段的安全整理

```text
选中段并固定存活集
→ 复制仍有效的记录到新段
→ 校验并持久化新段
→ 在 SQLite 事务内切换相应引用
→ 等待仍读取旧段的句柄/世代退出
→ 再确认没有当前引用
→ 删除旧段
→ 更新回收状态与宿主实际占用
```

整理器必须与写入协调：迁移引用时验证版本，不能覆盖同时发生的新写入。即使 V1 不提供用户快照，也存在活动读者和事务引用。不能仅凭一个未经核实的 refcount=0 就删段。

任一步中断可重复恢复，状态转换幂等。若切换失败，保留旧段；若切换成功而删除失败，多占空间等待重试。卸载时只完成/退出当前有界安全步骤，不为全盘整理长时间阻塞弹出。

### 6.3 空间不足

空间计算必须同时检查逻辑配额、宿主真实剩余、已预约写入、维护预算，不把待回收字节提前当成可用容量。

初始可测试一个明确展示的 256 MiB 应急预留文件及独立低空间水位；预留参数按卷大小和实测调整，不能隐藏这部分初始占用。

处置顺序：回收已完全失效的段；尝试安全完成删除元数据事务；在有足够工作空间时整理混合段；必要时暂停新写入而保留读取和允许的删除功能。绝不为腾空间先删掉尚未确认新副本的旧段。

外层 exFAT 上其他应用能消耗空间；软水位和释放预留文件都不是独占空间保证。即使释放预留后空间又被抢占，也必须正确返回 ENOSPC/平台对应错误，不能宣称一定写得进去。

## 7. 跨平台语义

V1 采用固定版本的跨平台名称比较规则：大小写保留、比较不区分大小写、规范化比较键一致。保留原始显示名；两个名字落入同一比较键时明确报冲突，不能静默合并或覆盖。拒绝双方不安全的保留名、字符及路径形式；导入提供可预览的显式改名，而不是暗中修改。

文件 ID 独立于路径。目录移动和重命名更新目录项；应用的临时文件替换保存流程需专门验证。单个 SQL 事务原子不等于整个应用保存工作流自动原子。

Mac xattr/Finder 信息/资源分叉保存在内层元数据或数据流，不落成外层每文件一个 AppleDouble。只有实际实现并验证完整属性接口后才允许声明这一能力。`.DS_Store` 属于普通卷内文件，不伪造“写入成功但丢弃”的行为。

Windows 属性、时间、共享/删除约束、ACL 的实际强制执行与继承、备用数据流、符号链接及硬链接均纳入兼容性矩阵。不能以“保留了属性”替代操作系统实际语义。符号链接、硬链接、执行、mmap、锁和监听不再一概推迟到后续版本；其中后端缺失标为 BLOCKED，不得标为通过。

原地写入应保留无关属性。应用创建新文件并替换旧文件时，不能保证旧文件属性自动继承，不应为追求表面保留而破坏原生语义。

V1 是正常开发工作盘，不是资料保险箱。Codex 本地工作区、Git（含 worktree）、Node/npm/pnpm、Python/venv/uv、Rust/Cargo、IDE 监听、项目内 SQLite/WAL 与原生编译产物执行均为必须验证的应用工作流。缺项不能靠把源码、依赖或产物复制到内置盘通过认证。系统启动、裸盘格式化、交换文件、Time Machine 等系统专属用途独立列出，不把它们与正常文件操作混淆。未实现操作返回明确错误，记录兼容缺陷；不伪报成功，也不把正常工作盘要求改成可选。

## 8. 独占、恢复与安全卸载

每容器一个 owner。OS 文件锁是主要同步手段，卷 UUID、会话 ID、进程标识用于诊断；仅有 lock 文件、PID 或时间戳不够。V1 拒绝第二个独立挂载实例，包括会绕开 owner 打开活动数据库的维护工具。

异常会话先进入恢复检查；不得仅因超时就抢锁。用户不能同时通过两台主机或两个虚拟机写同一介质。外层目录由用户随意改动、删除或同步也不在安全操作范围内。

挂载流程：识别卷与能力 → 获取独占所有权 → 检查异常退出 → 必要时先保全工作副本并恢复 → 一致性检查 → 挂载 → 恢复维护队列。遇到可疑损坏默认只读诊断，禁止自动格式化或在原件上“试修”。

安全卸载：停止接受新写 → 完成或取消有界维护事务 → 刷新数据与元数据 → 关闭挂载/句柄 → 释放容器所有权 → 请求 OS 弹出外层设备。外层仍被别的程序使用则显示具体原因，不强制弹出。

应提供独立 `verify` 和 `export` 工具。正常导出不依赖 GUI 或挂载驱动；损坏诊断应尽量只读，对 SQLite 需要恢复的情形在副本上处理。离线复制整个已卸载容器作为备份；不能复制一个正在变动的 catalog 文件并声称完整备份。

数据段自描述便于尽力提取，但若目录数据库严重损坏，不能保证恢复完整文件名、目录关系或每个文件版本。校验和不是冗余副本。同盘恢复点也不是设备故障备份。

底层 exFAT 不支持元数据日志和稀疏文件，容器日志不能消除宿主目录或分配结构损坏风险。[S1] 不承诺随意拔盘安全，不能直接修理外层 exFAT。任何稳定性声明须限定测试设备、系统和失败模型。

## 9. 界面与工具

主界面：创建/挂载/打开/安全卸载；显示逻辑配额、有效数据、回收站/引用保留、待回收、实际物理占用、宿主可用空间及应急预留。

状态明确区分：读写正常、维护中、等待文件释放、空间不足、未安全退出待检查、只读保护、离线。展示真实测量，不使用虚构速度、进度或“已安全”标志。

默认没有第二层自动保留的自建回收站；尊重平台回收站。不会在用户不知情时保留一周历史，造成“删除却不变小”。用户快照属于未来明确开启的功能。

拟议 CLI（均为设计，当前不可执行）：

```text
portaweave create /path/Work.pwvol --quota 800GiB
portaweave mount /path/Work.pwvol
portaweave status /path/Work.pwvol
portaweave gc /path/Work.pwvol --now
portaweave unmount /path/Work.pwvol
portaweave verify /path/Work.pwvol --read-only
portaweave export /path/Work.pwvol --to /other-disk/Export
```

`gc --now` 只是主动维护入口，不是正常使用前提。破坏性维护不得成为默认子命令。

## 10. 测试与发布门禁

故障注入从 M1 起就与实现同行，不能等“界面做完”才开始。WinFsp 官方测试覆盖文件语义、映射 I/O、故障和性能，可作为适配层测试来源之一。[S10]

### 必测集合

- core：模型比对、范围覆盖、目录树、名称冲突、稀疏逻辑区域读零、截断、文件 ID、重命名替换、错误传播。
- GC：删除整个大文件、共享段小文件删除、随机覆盖、打开后删除、GC 与读写竞争、每个迁移边界终止进程、重启后幂等。
- 持久化：短写、EIO、ENOSPC、刷新失败、截断 WAL、撕裂记录、丢失未持久化写入、宿主空间被外部程序占用。
- 安全：恶意格式输入、损坏长度/偏移、整数溢出、路径穿越、符号链接逃逸、IPC 越权、解析器 fuzz、资源上限。
- 平台：Finder/Explorer 复制移动、Office 类替换保存、视频读取、Quick Look/缩略图、句柄共享、内存映射、大小写变更、Unicode、xattr。
- 物理：同一 exFAT 设备 Mac→Windows→Mac；多种簇大小、SSD/HDD/U 盘与 USB 桥接；安全卸载、睡眠唤醒、异常拔出。破坏性测试仅限专用测试盘并得到授权。

测试目标起点可设：10 万次模型操作、每个事务与 GC 边界故障注入、100 次跨系统往返、大文件和大量小文件混合负载。数字不是安全证明；任何静默错读、已同步提交异常丢失、GC 误删或伪成功都是发布阻断项。

性能报告以同设备普通 exFAT 为基线，同时报吞吐、尾延迟、内存、写放大、整理临时空间和回收进度；不预先承诺达到 APFS/NTFS 的某个比例。

### 里程碑

| 阶段 | 产物 | 验收 |
|---|---|---|
| M0 平台可行性 | 真挂载、执行/映射/通知/链接/ACL/Codex 沙盒门禁；exFAT SQLite/刷新/锁验证 | 后端不能满足工作盘要求则修改选型，不以基础复制通过代替；保存 OS/版本/日志 |
| M1 存储核心 | 格式草案、CLI、元数据事务、追加段、自动 GC、校验、只读导出、故障模拟 | 无驱动也能验证数据与回收；故障矩阵结果可复现 |
| M2 双端闭环 | 两端适配相同核心与同一容器；开发工具和代理端到端 | 真机往返、Codex 改代码与运行测试、Git、依赖安装、监听、SQLite、执行逐项通过 |
| M3 安全与容量 | ENOSPC、回收竞争、恢复、真实介质测试、性能调优 | 发布阻断项归零；明确失败模型和已知限制 |
| M4 桌面测试版 | 管理 UI、安装签名、公证/安装检查、文档、升级与卸载 | 新机器可安装，卸载客户端不删除用户容器 |
| M5 稳定版 | 完整兼容矩阵与恢复演练、格式冻结 | 测试证据充分；仍不代替独立备份 |

Linux 原生 FUSE、加密、快照、去重、压缩与单文件归档安排在后续，不抢占 V1 正确性工作。Windows/WSL 访问另列测试矩阵，不以 Windows 原生通过代替 WSL 通过。正常开发依赖的链接和权限语义属于 V1 门禁。加密必须覆盖元数据、密钥管理、恢复和迁移，不能添加一个“密码框”就宣布完成。
