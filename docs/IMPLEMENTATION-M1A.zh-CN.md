# M1-A 实验性持久化核心

日期：2026-10-24。本文记录本轮代码的实际范围；SPEC v0.2 的“尚无核心”描述属于实现前基线。**目前不是可挂载的文件系统，不是可存储重要数据的产品。** 文档中的已实现不自动等于所有平台实测通过；测试证据另见 VALIDATION 和 PR #2。

## 已进入代码的能力

`crates/core` 提供 Rust 库，使用 SQLite 作为唯一权威目录，数据存放在真实的不可变段文件中，而不是内存模拟或普通文件夹透传。

- 创建新容器、关闭后重新打开、格式和最低 SQLite 版本检查、操作系统独占文件锁。
- 稳定对象 ID；目录创建、查询、移动、删除；原子替换；真正共享对象的硬链接与链接计数；拒绝目录循环。
- 分块随机读写、逻辑空洞读零、截断和重新扩展；缩短文件后清除末块尾部，防止重新扩展暴露旧内容。
- 文件取消目录链接后，打开的句柄仍持有对象；最后一个句柄关闭后才可释放对象。
- 有界读取租约保留旧块引用；覆盖文件后旧读取仍能完成，回收不会提前删除被租用的数据段。这不是 OS mmap 或用户快照。
- 新数据同步后提交数据库引用；SHA-256 校验；遇到不明确的 I/O/SQL/校验错误进入写保护。
- 每次成功变更及句柄/租约释放后，自动删除无引用整段，并最多整理一个有效块比例不高于 50% 的混合段。整理先写新副本、再提交引用、最后删旧段。
- 当前引用全量校验后，重新打开时回收上一会话留下的无句柄孤儿和无引用段。

## 重要限制与偏离最终规格

格式名为 `experimental-m1a-block-v1`，目录使用 `format.txt`，尚无稳定版本升级或卷 UUID。数据块固定 64 KiB，一次写入生成一个新段；这便于验证正确性，但小文件放大和大量段文件的问题尚未优化，不是最终 64 MiB 聚合策略。

维护目前在串行引擎操作内执行，不是空闲后台线程。它已经不需要调用者日常手动 compact 才能触发，但还没有低优先级调度、全量维护预算、应急预留或完整磁盘写满策略。逻辑配额已实现，真实宿主余量预约仍待开发。Stats 的段字节数只统计被跟踪的段文件长度，**不是整个容器在 exFAT 上的实际分配大小**；SQLite/WAL、目录、簇和预留需另计。

正常开发盘需要的符号链接、权限/ACL、可执行位、时间戳、xattr/ADS、文件监听、系统缓存与 mmap、Windows 共享标志均未完成。核心硬链接通过不意味着 WinFsp 的挂载接口限制已解决。Issue #1 的真实挂载/Codex 门禁仍必须完成。

库的 `verify()` 不是独立只读恢复工具：`open()` 会进行 SQLite 恢复及自动回收，**不要拿它检查唯一原件或可疑损坏介质**。只读诊断、离线导出、保全副本与安全升级是下一阶段阻断项。原始 backing 目录必须受独占控制，目前不提供对恶意并发改写原始文件的安全边界。

## 持久化与错误语义

文件同步错误会返回给调用方。Unix 目录同步使用系统调用；Windows 目录持久化尚无经过验证的实现，macOS 更强持久化和 USB 控制器行为也未验证。因此尚未提供或宣称完整 OS fsync/FlushFileBuffers 语义，不可用来承诺断电安全。

业务写入可能已提交，而随后的维护失败。返回错误**不保证整个业务操作已回滚**；调用方不能盲目重试，需要查询状态并尊重写保护。后续平台适配应将事务结果与维护状态分离，避免应用误解。

故障注入 feature 默认关闭，仅供测试；能够在数据同步后、元数据事务提交前/后、整理引用切换前注入错误，子进程测试可在边界直接退出且不运行析构。它验证进程中断恢复，不模拟设备丢弃已确认写入或 exFAT 分配表损坏。

## 开发者运行

只针对全新、可丢弃路径；不要放入用户重要数据。需按 `rust-toolchain.toml` 使用锁定工具链，依赖由 Cargo.lock 固定。

```sh
cargo test --workspace --all-features --locked
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo fmt --all -- --check
cargo run --locked -p portaweave-core --example scratch -- /path/to/new-disposable-lab
```

示例会创建真实数据段、验证硬链接和打开后删除、关闭最后句柄触发回收，再关闭并重新打开容器。它不会挂载磁盘，不会安装驱动，也不会格式化设备。
