# ADR 0016 — FSKit directory item references and atomic pin creation

Date: 2026-10-27. Status: laboratory FSVolume/core/native implementation; actual native mounts remain blocked.

M1-O added v3 directory inode references, but the SDK adapter retained none of its own. Its old contract needed an external policy pin to keep a removed directory alive. Cached directory FSItems could otherwise lose their inode, and the adapter rejected open-directory removal/replacement as BUSY. This differs from the cached regular-file identities already retained until reclaim.

Apple distinguishes retained open modes from reclaiming an FSItem after the upper layers release their references. See the official [OpenCloseOperations](https://developer.apple.com/documentation/fskit/fsvolume/opencloseoperations) and [reclaimItem](https://developer.apple.com/documentation/fskit/fsvolume/commonoperations/reclaimitem%28_%3Areplyhandler%3A%29) contracts. Apply that distinction to the fixed macOS26 Operations SDK. Do not substitute macOS27 Handler/FSContext signatures or assume kernel dispatch was tested.

In NEW explicit v3 volumes, a cached non-root directory FSItem owns one administrative DirectoryHandle until reclaim. Lookup interns one typed reference and reuses it for later lookups of that identity. Creation reserves a pending SDK item and the native/core pin BEFORE mutation, projects initial attributes BEFORE commit, publishes the core pin BEFORE maintenance, then publishes the prepared C/SDK result without a fallible follow-up open/query. Add a separate `create_directory_with_pin` result/API; ordinary directory creation remains unpinned in every format. v1/v2 schema and legacy adapter behavior remain unchanged. No format or capability change/migration is needed.

Administrative directory pins get their own C table and output type, separate from administrative files, policy directory grants, cursors and leases. All four file/directory pin tables share the core 4096 budget and native BUSY checks. A file close, policy close or cursor close cannot consume an administrative directory token. Refusals publish no pin/item, preserve output/parent/namespace, and do not poison health. Current business/maintenance outcomes and release under protection keep their existing rules. Logical counts are not exact heap/OOM reservations.

Open modes continue describing access retained by FSKit. `closeItem(..., modes: [])` clears that access; it does not drop the separate cached identity reference. `reclaimItem` rejects still-open items, releases only its own metadata cursors/reference, then removes the cached identity. A removed or replaced empty directory remains observable/settable while its cached item exists; final reclaim collects an unreferenced orphan. Old SDK objects then return ESTALE. The root is never unlinked and needs no extra pin. Deactivation still refuses active references; it never forces owner release.

v3 removal/replacement may proceed with a read-open directory because its inode is retained. Preserve transaction-checked source/target IDs. No directory data writes, new orphan children, fake dot/parent lookups or native directory linkCount are introduced. Normal close/reclaim/synchronize remain distinct from safe device eject. SDK setter/lookup/create callbacks remain administrative lab operations, NOT caller authentication or the mode-only policy grant. Keep access/probe/load/activate/mount closed, as well as Windows security/Open/Flush.

Validate atomic initial state, full shared admission, default creation, all legacy refusals, wrong/foreign/stale tokens, duplicate concurrent creates, pre/post-commit faults and real process exits. Exercise actual C callers on all OS runners, real SDK create/lookup/open/unlink/replace/close/reclaim and 4096-pin refusal, full unsigned App/Extension build, and same-container artifact handover. The existing fixed old-reader rejection and original-preserving recovery remain mandatory. No direct SDK/caller result establishes system mounting, OS identity/ACL, cache coherence, application sandbox compatibility, exFAT or physical power-loss safety.
