# ADR 0020 — Opt-in native owner idle worker with stop/join before release

Date: 2026-11-03. Status: implementation increment; exact-source CI pending at authoring.

M1-R provides serialized candidate steps but no timer. Add an explicit administrative worker start/stop/status API on the existing native session. Core create/open do not implicitly launch threads. The scratch-only WinFsp laboratory owner opts in after successful core creation with idle=30000ms / interval=1000ms; all access/Open/security/Flush gates remain closed. FSKit App/Extension do not start a worker while resource/load gates are closed.

The thread owns only its session ID and stop receiver. It never opens or clones Volume, SQLite, a catalog connection or the owner lock. It waits with recv_timeout, then TRY-locks the existing process registry. Contention yields to foreground work; poisoning exits rather than recovering an inconsistent registry. It must not block on that mutex. An admitted step uses the same core object/tables as ordinary requests.

Foreground requests mark activity both before and after completion, so a long operation gets a full quiet period after it returns. Health/space/worker-status polling and the explicit maintenance step do not count as foreground I/O. Due time uses process-local monotonic Instant, not wall time. Successful progress continues at the configured interval; zero-progress/pinned/preflight-space-deferral backs off by max(idle,interval). Only the core HostSpace variant retries: actual I/O StorageFull can map to the same C NO_SPACE but must stop after core protection latches. Other errors stop; the core health and worker last_status remain visible. Last report means the last successful step, never rollback of partially completed cleanup. Ticks are saturating diagnostics, not capabilities.

Start validates 10..600000ms idle and 10..60000ms interval. A second start returns BUSY, even for a finished worker until stop releases it. Protected owners refuse start. Thread-launch failure does not publish controller state or alter storage health; it is an error of the explicit administrative start. The same registry guard prevents the spawned thread from accessing an incompletely published session/controller.

Stop is idempotent, sends a channel wake and joins before dropping controller state. It can run under the registry lock because the worker never waits for that lock and recv_timeout is interruptible by the channel. A busy volume_close leaves the worker and all pins alive; successful close first stops/joins, then drops the sole core owner. Session controller field/drop order is before Volume, including unwinding. Explicit join errors are returned while the owner remains registered; Drop cannot report them. Close all owners before unloading the native library. A currently admitted core step finishes before a stop caller acquires the registry: no forced thread termination, SQLite interruption, hard stop latency or safe-eject promise.

The WinFsp lab explicitly stops/joins before destroying platform state and closing its owner. Driver installation, real dispatcher execution and OS shutdown/logoff behavior remain separate authorization/tests. C smoke tests start/join real threads but do not wait 30s or certify kernel dispatch. A separate native integration test uses an actual short monotonic quiet timer and an ended-owner backlog to prove automatic cleanup without another business mutation while health/space/status are polled.

This is cooperative scheduling under a process-wide registry mutex. Continuous foreground contention can postpone admission; SQL/cascade/sync latency and whole-GC resource budgets remain unresolved. It is not OS caller authentication, ACL enforcement, full durability, install/enable, true mount or developer-volume certification. v1/v2/v3 schemas/markers/defaults are unchanged.
