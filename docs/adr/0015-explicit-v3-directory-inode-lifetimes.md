# ADR 0015 — Explicit v3 directory inode lifetimes

Date: 2026-10-27. Status: experimental versioned core/native contract; native mounts remain unvalidated.

M0-T/U metadata cursors do not retain a directory inode. Both old formats reject unnamed non-root directories, so retaining a removed/replaced directory across a committed transaction cannot be added by merely changing GC. A process can disappear between namespace commit and final close. Ordinary open, original-preserving recovery and old readers must agree about that persisted state.

Add a NEW opt-in `experimental-m1o-directory-v3` format, exact schema/user_version 3 and required capabilities 3 (metadata bit 0 plus directory-lifetime bit 1). Default creation stays v1, metadata creation stays v2, and neither is migrated. Their schema files and orphan-directory rejection remain unchanged. v3 still has one owner, SQLite authority and the same immutable segments. The pinned actual pre-v3 reader must refuse v3 without changing output or source-file hashes; never rewrite a marker to make an old reader accept it.

Use separately typed administrative `DirectoryHandle` and trusted `PosixDirectory` references. All file/directory pins share the existing core 4096 admission gate. Directory creation itself admits no pin. READ+SEARCH and all ancestors are checked when admitting a policy directory reference. That grant can subsequently observe the current inode and capture metadata after rename, chmod, ancestor revocation or last unlink; it grants no future namespace mutation authority. Known-ID namespace operations still refuse unlinked directories. Raw administrative observation/admission is not caller authorization. Lifecycle tokens are process-local identifiers, not persistent credentials or unguessable secrets.

v3 remove and replacement delete the directory entry and update the retained inode's metadata in the SAME transaction. Only empty, zero-size, zero-block unnamed non-root directories are valid. No new children or invented dot/parent entries may appear in them. Existing pins retain the inode; last close triggers ordinary serial maintenance. New owners verify first and reclaim abandoned unpinned directories. Recovery copies and strictly verifies them, reports them separately and does not export an invented pathname or modify the source. Nonempty/data-bearing orphans, multiple directory links, cycles and unreachable linked subtrees remain corrupt. v1/v2 still reject all unnamed non-root directories.

Current owner/group authority for metadata changes is independent of the old read grant. Reuse the existing policy and a pure, fallible pre-commit reply projection. A data/read grant never bypasses a subsequent owner change. Business success and maintenance protection remain separate; releasing a pin under protection must remain possible.

The native ABI adds a separate directory-grant table, included in BUSY and common pin admission. Immutable Windows cursors still retain metadata only and share the old 64-cursor/100000-entry limits. A snapshot captured through a grant may outlive the pin and final inode reclamation. Its ordinal cookies/EOF rules do not change; an unlinked directory has no dot rows. Entry/pin counts are logical admission limits, not exact heap/peak-memory bounds.

The lab WinFsp context carries a separate directory grant. GetFileInfo and pre-commit SetBasicInfo can use it; metadata setters still need explicit current trusted claims. Close releases snapshot and grant separately. No automatic concurrent C context refresh is introduced. The SDK contract observes a cached FSItem while an EXTERNAL trusted native directory pin exists; it is not FSKit native Open or authenticated caller binding. Internal directory entry counts are not advertised as native directory st_nlink. WinFsp HardLinks remains zero with the upstream gap BLOCKED.

Keep WinFsp security/Open/Flush and FSKit access/probe/load/activate/mount closed. Validate default/all-feature core, real subprocess exit boundaries, shared-budget/typed-token/concurrency refusal, actual C/MSVC and SDK consumers, unsigned App/Extension build, and the SAME v3 artifact across OS runners. Distinguish intentionally abandoned-owner fixtures from safe unmount and physical power loss. Real exFAT, mounted applications, Codex's normal sandbox and denied escapes remain independent release gates.
