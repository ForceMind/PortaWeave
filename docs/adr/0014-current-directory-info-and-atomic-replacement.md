# ADR 0014 — Current linked-directory observation and atomic snapshot replacement

Date: 2026-10-27. Status: experimental core/native/direct WinFsp callback; no native mount authorization.

M0-T's owned metadata can survive rename, chmod and directory removal. Serving those captured attributes as current GetFileInfo would be incorrect. Add a distinct observation on the snapshot's captured object ID with fresh trusted READ+SEARCH and every-ancestor search checks. Observe current FileInfo and project it before writing output. No old pathname is re-resolved to a replacement object. Removal returns NotFound even while the old bytes remain readable; malformed/unrepresentable times do not fall back to captured values.

This is intentionally not a live directory descriptor. Existing v1/v2 rmdir/replacement deletes the directory object, and both normal verify and original-preserving Recovery reject unnamed non-root directories. Retaining such an object across commit/crash requires a separate format/backward-reader/recovery decision. Do not silently change those invariants, invent an orphan inode from old attributes, deny deletion forever or mislabel a metadata cursor as an open grant. Full open-after-rename/unlink directory semantics remain a release requirement.

Explicit refresh prepares a new snapshot of the SAME object, reauthorizing against current ancestors/mode. Count and project all entries, then reserve a new monotonic process-local token before replacing the old table entry under the native owner mutex. A rejection leaves the old token, bytes, outputs and foreign cursors intact. Policy/count/projection refusals do not poison writes; genuine observed I/O/corruption still follows the existing protection latch. Successful replacement retires the old token and returns the new token plus attributes captured with its new listing. Old reads either finish entirely before replacement or fail unchanged afterward. Callers restart ordinal cookies at zero and discard old cookies; the API cannot identify an old ordinal when deliberately paired with a new token.

Replacing a known Windows cursor uses no additional published cursor slot and credits only that cursor's retained entries. At the common 64-cursor/100000-entry limit it may replace itself, never evict administrative cursors, other Windows snapshots or file pins. Old and prepared data temporarily coexist; these admission counts are not peak heap/OOM bounds. The test-only lower ceiling remains test-only. Closing or replacing metadata uses no data GC or inode/data pin.

The actual WinFsp GetFileInfo callback may use the fresh-info entrypoint only with explicit lifetime-valid trusted test claims. NULL denies before the bridge; no daemon/root fallback or POSIX-mode-to-ACL mapping. Output is DIRECTORY with zero logical size/allocation, supported times/stable ID and upstream-required HardLinks=0. This READ+SEARCH laboratory profile does not implement Windows READ_ATTRIBUTES, native SID/ACL or an authenticated caller. ReadDirectory NULL Marker/offset=0 continues replaying its existing snapshot; no automatic restart refresh or concurrent C context-token swap is introduced. The direct C contract explicitly replaces its token sequentially and discards old cookies.

Keep WinFsp security/Open/Flush and FSKit access/probe/load/activate/mount closed. The Swift SDK contract is an actual consumer of the additive native ABI at full admission, not new FSKit caller authorization or OS dispatch. Validate current-vs-captured values, rename/ancestor revocation, deletion/name replacement, failed outputs, projection/count refusal, 64 mixed cursors, concurrent read/replace and cross-OS core handover. Windows MSVC, SDK objects, full bundle, actual mounts and physical media remain separate evidence levels.

M1-O follow-up: [ADR 0015](0015-explicit-v3-directory-inode-lifetimes.md) adds separately typed live references ONLY to a NEW opt-in v3 format. This ADR's linked-current APIs still reauthorize, and v1/v2 orphan-directory invariants are unchanged. A metadata cursor remains a metadata copy.
